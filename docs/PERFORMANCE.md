# 性能測定（2026-09-07）

Apple M4 Max / macOS / Node.js 22.18.0 / Playwright Chromium 153.0.8010.12、ローカルViteサーバーで測定しました。グリッドは4列、高さ500px、1千・1万・5万行です。比較元はGitの`b34cd1d`にあるDataGridの実コードです。初期表示は1回、ソートは7回で中央値と最大値をp95として記録しています。厳密な母集団の95パーセンタイル推定ではありません。

## モデル操作

節点N、部材N−1、荷重ケース1、最大履歴10件のモデルを各5回測定しました。編集直後のUndoを繰り返し、2チェックポイントを保持する条件です。測定はサービス処理の時間で、UI全体の応答時間やディスク保存完了時間ではありません。

|節点数|編集p50 変更前→後(ms)|読込p50/p95|検索p50/p95|Undo p50/p95|JSON生成p50/p95|Undo可否|
|---:|---:|---:|---:|---:|---:|---|
|1,000|15.3 → 1.9|3.0/4.8|0.4/0.7|3.4/3.8|1.4/1.6|可|
|10,000|156.7 → 19.6|27.5/29.5|3.1/3.3|32.2/34.7|13.2/13.5|可|
|50,000|794.1 → 95.8|144.7/145.7|9.4/21.3|167.7/184.6|63.9/64.0|可|

変更前は今回の初期実装（整形JSON・16MiB・全体の正規化比較）です。変更後は空白を省いたチェックポイント、64MiB、形式が固定されているDTOの比較、トランザクション内の重複記録除去を含みます。1万／5万節点で失われていたUndoが保持されました。上限を超える場合は履歴件数を削減します。5万節点のJSONは約63MB、復旧ペイロードは約109MBで、履歴の64MiB以外に保存済み状態やJSON文字列などの領域が必要です。

節点・部材のバッチ描画により、このケースでは50,000節点でも資源数は一定でした。選択は20回測定しました。荷重・壁・局所軸矢印・結果再生を大量表示したケースの上限値ではありません。計測後の目安を、同機種の5万行ソートp95 50ms以内・選択p95 16ms以内・サービス編集p95 200ms以内とします。これらを満たしたため空間索引・差分履歴への追加変更は見送りました。大規模モデルのメインスレッド全体処理は残り、別機種で同じ応答を保証しません。

JSヒープ値はChromiumの`performance.memory`の概算値を生データに記録しています。今回の実行では同じ丸め値を返すため、正確なメモリ改善率の根拠には使用しません。GPU資源はrenderer.infoによる件数で、GPUバイト数ではありません。

## 再現

`npm run benchmark`で測定を再実行できます。実行ごとに[グリッド・3Dの生データ](benchmarks/latest.json)、[モデル操作の生データ](benchmarks/workflows.json)を更新します。[履歴最適化前の記録](benchmarks/workflows-before-history.json)も保持しています。測定用の旧ソースはGit管理対象外の`.benchmark-baseline`へ取り出します。
