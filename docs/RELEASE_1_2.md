# Version 1.2 — 編集・復旧・交換機能

## 操作

- **復旧センター**: 右上の状態表示から、このブラウザーの復旧候補を復元・削除できます。モデルとタブの編集セッションごとにIndexedDBへ保存し、旧localStorageデータは検証後に移行します。保存失敗も同じ場所に表示します。JSONダウンロード後も復旧候補を保持します。
- **ファイル読込**: JSON/YAMLの件数、入力単位、補正・エラーを確認してから適用します。取消時や読込中にモデルが変更された場合は置換しません。YAML出力の未対応項目はダウンロード前に確認できます。診断はJSON・CSV・Markdownで保存できます。
- **CSV入力**: 現在のタブで列対応、番号をキーとした追加／更新、cm/kNまたはmm/Nを選びます。空セルは変更せず、全件の確認後に適用します。意味が未確定の密度・壁パラメータ・部材荷重などの単位換算は拒否します。
- **貼り付け・一括属性**: 選択範囲に適用する値を確認できます。貼り付けはエラーを含む場合に全件を止め、一回のUndoで戻せます。
- **グリッド**: クリックまたはF2/Enterで編集、Escapeで未確定値を取り消し、移動モードの矢印でセル間を移動します。IME変換中のキー操作を横取りしません。Tabでグリッドを離れます。200行超は固定高の行ウィンドウを使います。
- **配列複製**: 複数選択した節点・部材・壁を直線複製できます。回転・鏡像は節点と部材に対応し、共有節点、節点荷重、支持方向、局所軸を引き継ぎます。回転規約が未定義の壁・部材荷重・CMQや、拘束・質量・リンク・不透明な拡張情報を含む操作は明示的に拒否します。方向別支持の一般角回転も拒否します。
- **骨組テンプレート**: スパン数、層数、寸法、既存断面を指定して平面骨組／トラス形状を生成します。支持・荷重と解析用の断面種別は利用者が設定します。既存モデルへ追加するため、重複位置は健全性センターで確認してください。
- **プリセット**: 断面計算入力・材料、カメラ・表示レイヤー・色分け・ラベル密度を保存し、JSONで持ち運べます。同名の別プリセットを黙って上書きせず、版・単位・寸法を検証します。
- **局所軸**: x赤／y緑／z青の矢印を表示できます。部材を選ぶとI/J番号、軸ベクトル、指定／推定、単位を表示します。

## 交換仕様

公開契約は[Frame JSON v2](../public/schemas/frame-v2.schema.json)と[結果JSON v1](../public/schemas/results-v1.schema.json)。[正常モデル](../public/samples/contracts/frame-v2.json)、[正常結果](../public/samples/contracts/results-v1.json)、[不正単位の結果](../public/samples/contracts/invalid-result-units.json)を同梱しています。

JSON Schema 2020-12は**シリアライザーが出力する正規形式**を記述します。旧モデルの省略項目・別名・v1移行や結果の配列ベクトルを直接列挙した入力仕様ではありません。既存パーサーはこれらを正規化して引き続き読み込みます。strictは不正な型を拒否し、lenientは診断を伴う既定値への補正を行います。番号の参照整合、零長、荷重ケース数との一致などはアプリのモデル検証が担います。

モデルはcm、kN、面積cm²、断面二次モーメントcm⁴、応力kN/cm²を使用します。結果の変位はcm、回転はrad、力はkN、モーメントはkN-cmです。節点変位・反力はglobal-xyz、部材力はlocal-xyzです。

結果v1に任意の`modelFingerprint`と部材の`stations`を追加しました。位置はI端0からJ端1へ厳密に増加し、両端を含みます。中間点がない場合は端点を結ぶ表示です。分布荷重下の曲線を端点だけから推定しません。SHA-256指紋はタイトル・表示状態・表示荷重ケースを除く正規化モデルに対応します。指紋のない旧結果は参照番号だけを照合するため、同じ番号を持つ別モデルとの一致は保証しません。

## OpenSees連携

1. 解析結果パネルで「解析用モデル対応情報を保存」を選び、解析開始時の`analysis-binding.json`を保持します。
2. [export_results.py](../examples/opensees/export_results.py)を外部解析から呼び出します。対応範囲は3Dの`elasticBeamColumn`、`Linear`変換、端部オフセット・リリースなしです。実際の構築時に使った`vecxz`を渡します。解析に使った材料・断面・荷重とbindingの対応管理は呼出側が担います。
3. 出力された`opensees-recorder-v1` JSONを結果パネルで読み込みます。節点・要素タグ、座標、I/J接続、局所y、指紋、単位を検証してから表示します。

入力単位はcm/mm/mとkN/N、時刻sです。`localForce`の順番はI端のN,Vy,Vz,T,My,Mz、続いてJ端の同6成分。アダプターはI端6成分の符号を反転し、J端を維持して、正の局所x面に作用する断面力へ揃えます。任意の中間`stations[].force`はすでにこの断面力規約で渡します。

[cantilever.py](../examples/opensees/cantilever.py)は別途OpenSeesPyで計算する再現例です。2026-09-07にOpenSees 3.4.0（macOS x86_64をRosetta実行）でL=100cm、P=-1kN、EI=1,000,000kN-cm²を照合しました。自由端変位-1/3cm、回転-0.005rad、根元反力1kN・100kN-cmに一致し、実出力をテスト用に固定しています。ブラウザー内にソルバーは含めません。

局所軸規約は[OpenSees Linear Transformation公式資料](https://opensees.github.io/OpenSeesDocumentation/user/manual/model/geomTransf/Linear.html)、端力配列は[公式実装](https://github.com/OpenSees/OpenSees/blob/master/SRC/element/elasticBeamColumn/ElasticBeam3d.cpp)を参照してください。

## 容量と性能

履歴は改行・字下げを省いたJSONチェックポイントで、最大100件・64MiBの**履歴スナップショット合計**を目安に古いものから削減します。現在の1件は上限を超えても保持し、保存済み比較情報・DTO・復旧JSONなどの作業領域はこの上限に含まれません。ブラウザー全体のメモリ上限を保証する設定ではありません。復旧はIndexedDBの空き容量に依存します。

大きなJSON/YAMLの解析・検証はWorkerで行い、古い要求を終了させます。読込ファイル上限は100MiBです。解析後のDTO適用、編集、Undo、書出しにはメインスレッドでの全体処理が残ります。[測定結果](PERFORMANCE.md)で対象規模と制約を確認してください。保存成功は復旧データの書込み成功、JSON保存の表示はダウンロード開始を意味します。

## ローカル検証と公開

Node.js 22.12以上の22系または24系を使用します。`npm run verify`、`npm run test:e2e`をローカルで実行できます。E2Eのブラウザーは`npx playwright install chromium firefox webkit`で準備します。IME試験は合成した変換中イベントの非干渉を確認するもので、OSのIME候補ウィンドウの自動試験ではありません。

`npm run schemas:generate`と`npm run examples:generate`で契約ファイルを再生成し、単体テストで適合を確認できます。性能測定は`npm run benchmark`。比較元`b34cd1d`がローカルGit履歴に必要です。

共有CIのpush／PRトリガーは維持します。今回の作業ではコミットの`[skip ci]`で自動実行を省き、ローカル検証後にマージし、Pagesの`workflow_dispatch`を一回実行します。以後、通常のコミットでは従来どおり自動CI／Pages公開が動きます。
